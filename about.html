Purpose

What is this tool
and why does it exist?

Planning a drone survey mission manually is tedious and error-prone. This tool automates everything from area definition to obstacle avoidance to battery budgeting — in a single HTML file that runs entirely in your browser.

🗺️

Aerial Survey Planning

Draw a polygon over any real-world area on a live satellite map, configure camera and flight parameters, and automatically generate an optimised lawnmower coverage path with numbered waypoints.

🚫

Guaranteed No-Fly Exclusion

Mark restricted zones (buildings, hazards, restricted airspace). Three independent algorithm layers guarantee the generated path never enters those areas — neither waypoints nor transition segments.

🔋

Battery & Time Telemetry

Given cruise speed and endurance, the planner estimates total distance, mission time, and battery consumption — and warns you before you launch with insufficient charge.

🤖

Multi-Drone Swarm

Split any mission across up to 5 drones. The boundary is partitioned into equal vertical strips; each drone independently plans and flies its own lane simultaneously, reducing mission time by ~N.

🎬

Live Flight Simulation

Visualise all drones flying their missions simultaneously in the map, with bearing-correct rotating icons, a progress bar, elapsed time, distance flown, and simulated battery drain.

📤

KML Export

Export the full mission as a standard .kml file compatible with QGroundControl, DJI Pilot, Mission Planner, or Google Earth. Altitude is stored as relative-to-ground AGL.

📋

Drawing Engine

The interactive
polygon drawing system

A fully custom, from-scratch drawing engine replaces Leaflet.draw, eliminating version compatibility bugs and providing a tight, responsive UX with multiple ways to complete a shape.

Drawing State Machine

The engine maintains a drawMode state ('boundary', 'zone', or null) and a draftPoints array of [lng, lat] pairs. Every map click appends a point. Every mouse move updates a live rubber-band preview line from the last placed point to the cursor.

💡
Multiple Completion Methods
Shape can be closed by: clicking the first point (highlighted green), pressing Enter, double-clicking (≥3 points), clicking Finish in sidebar, or clicking Finish in the on-map HUD. All routes call the same finishDrawing().
⌨️
Keyboard Shortcuts
Enter Finish · Backspace / Ctrl+Z Delete last point · Esc Cancel

Coordinate System

Draft points are stored as [longitude, latitude] pairs (GeoJSON order) for Turf.js compatibility. Leaflet uses reversed [lat, lon] order, so all rendering swaps the pair. The closed ring always appends the first point as the last element:

Polygon Ring Closing
ring = [...draftPoints, draftPoints[0]] polygon = turf.polygon([ring])

Grid Engine

Coverage path generation —
six-stage algorithm

The core of the planner is a deterministic, 100%-coverage path planner built from scratch in pure JavaScript with no dependencies beyond Turf.js geometry helpers.

Stage 1 — Row Spacing Calculation

The distance between adjacent flight rows derives from camera swath width and desired image overlap:

Row Spacing Formula
spacingM = max( swathWidth × (1 - overlap), 3 ) // metres, minimum 3 m spacingDeg = spacingM / 111320 // convert m to decimal degrees latitude
📐
Example
Swath = 40 m, Overlap = 70% → Spacing = 40 × (1 − 0.70) = 12 m between rows → 12 ÷ 111320 ≈ 0.0001078°

Stage 2 — Horizontal Scanline Decomposition with Interval Subtraction

A horizontal scan line sweeps from the bottom to the top of the bounding box at each spacingDeg step. At each latitude y, all polygon edge crossings are found and paired into flight segments. Obstacle intervals are then subtracted:

Scanline Intersection (per polygon edge)
If (y1 <= y < y2) or (y2 <= y < y1): // edge crosses the scan line t = (y - y1) / (y2 - y1) x = x1 + t × (x2 - x1)
1D Interval Subtraction with 2 m Safety Buffer
buf = 0.00002 // ~2 m clearance margin in degrees For each boundary interval [a, b] and obstacle interval [ox1, ox2]: No overlap → keep [a, b] unchanged Partial left → keep [ox2+buf, b] Partial right → keep [a, ox1-buf] Split centre → keep [a, ox1-buf] + [ox2+buf, b] Full overlap → discard interval entirely

Stage 3 — Cellular Decomposition

Raw scan segments are grouped into continuous cells — vertically contiguous columns of overlapping intervals. Each cell becomes its own independent lawnmower sub-mission, preventing paths from jumping across no-fly gaps.

🧩
Why Cells?
Without cells, a row-by-row lawnmower would draw a straight line from the last point of one row to the start of the next, potentially crossing an obstacle. Cells isolate each continuous region so transitions only happen within the safe, clear corridor of that region.

Stage 4 — Boustrophedon (Lawnmower) Waypoints

Within each cell, rows alternate left-to-right and right-to-left. Each row contributes exactly 2 waypoints:

Direction Alternation
ltr = (rowIndex % 2 === 0) // even = left-to-right startX = ltr ? seg.x0 : seg.x1 endX = ltr ? seg.x1 : seg.x0

Stage 5 — Nearest-Neighbour Cell Sequencing

Cells are ordered to minimise total transit distance using a greedy nearest-neighbour heuristic. Starting from the top-left cell, it always picks the next unvisited cell whose start is closest to the current end point (Haversine metric).

Stage 6 — Dijkstra Obstacle-Avoidance Routing & Final Safety Scan

Dense Sampling Penetration Test

20 intermediate points are sampled along each transition segment. Any sample inside an obstacle (ray-casting) flags the segment unsafe.

Edge Intersection Test

Parametric line-segment intersection is checked against every obstacle polygon edge. Small epsilon (0.001) prevents false triggers at shared endpoints.

Visibility Graph Construction

Navigation nodes: start point, end point, plus all obstacle corner vertices buffered 10 m outward from their centroid. Edges connect any two mutually-visible nodes.

Dijkstra Shortest Path

Dijkstra runs on the visibility graph from start to end. Edge weights are Haversine distances. The result is the shortest safe detour around all obstacles.

Final Safety Verification Pass

Every consecutive waypoint pair in the assembled mission is re-checked. Any remaining unsafe segment is rerouted. This double pass guarantees 100% obstacle-free paths.

No-Fly Zone System

How no-fly zones are
enforced at every level

Three independent, layered mechanisms ensure the drone never enters a restricted area — from the raw coverage grid, through inter-cell transitions, to the final assembled waypoint sequence.

📐

Layer 1 — Interval Subtraction

At every scan latitude, the obstacle's intersection interval is subtracted from the boundary's intervals before any waypoints are placed. Waypoints can only be generated in the obstacle-free remainder, with a 2 m clearance buffer on each side.

🧭

Layer 2 — Dijkstra Cell Routing

Cross-cell transition segments are routed via the visibility graph + Dijkstra's algorithm, threading the shortest path through safe corridors. Obstacle corner nodes are pushed 10 m outward for edge clearance.

🔬

Layer 3 — Final Safety Scan

Every consecutive waypoint pair in the assembled mission is re-tested with the full penetration check (dense sampling + edge intersection). Any remaining unsafe pair is rerouted. This final pass catches all edge cases.

Ray-Casting Point-in-Polygon

Ray Casting Algorithm
For each polygon edge (xi,yi) → (xj,yj): crossesY = ((yi > lat) !== (yj > lat)) crossesX = (lng < (xj-xi) × (lat-yi) / (yj-yi) + xi) if crossesY && crossesX: inside = !inside Odd crossings = point is INSIDE

Segment Intersection Test

Parametric Line-Segment Intersection
denom = (y4-y3)(x2-x1) - (x4-x3)(y2-y1) ua = [(x4-x3)(y1-y3) - (y4-y3)(x1-x3)] / denom ub = [(x2-x1)(y1-y3) - (y2-y1)(x1-x3)] / denom Intersects if: 0.001 < ua < 0.999 AND 0.001 < ub < 0.999

Pre-flight Telemetry

How every number
is calculated

All telemetry is computed client-side from the generated waypoints and slider values. No GPS, no server, no external API — pure geometry and physics.

Haversine Distance

Each consecutive waypoint pair distance is computed using the Haversine formula, which accounts for Earth's spherical geometry:

Haversine Formula
R = 6,371,000 // Earth radius (metres) dLat = (lat2 - lat1) × π/180 dLon = (lon2 - lon1) × π/180 a = sin²(dLat/2) + cos(lat1)cos(lat2)sin²(dLon/2) dist = 2R × arcsin(√a)

Mission Time & Battery

Total distance is divided by cruise speed to get flight time, then compared against maximum endurance:

Time & Battery Formulae
totalDist = Σ haversine(wp[i], wp[i+1]) timeMin = totalDist / (cruiseSpeed × 60) battery% = (timeMin / maxEnduranceMin) × 100
Swarm Parallel Time
missionTime = max(drone[1..N].timeMin) // Wall-clock time = slowest individual drone

Flight Simulation

Real-time drone
flight animation

The simulation engine animates all drones simultaneously using requestAnimationFrame, interpolating position along the waypoint path and rotating the drone icon to face its direction of travel.

Path Metadata Build

Each drone's waypoints are preprocessed into a leg list with cumulative distances, enabling O(n) position lookup:

Cumulative Distance Preprocessing
For each leg i → i+1: leg.dist = haversine(wp[i], wp[i+1]) leg.cumStart = Σ dist of all prior legs

Position Interpolation

At each frame, elapsed seconds × speed × multiplier = metres flown. The active leg is found, then lat/lon is linearly interpolated:

Linear Interpolation on Active Leg
distCovered = simElapsed × speed t = (distCovered - leg.cumStart) / leg.dist lat = from.lat + t × (to.lat - from.lat) lon = from.lon + t × (to.lon - from.lon)

Bearing Calculation (Icon Rotation)

Forward Azimuth
y = sin(Δlon) × cos(lat2) x = cos(lat1) × sin(lat2) - sin(lat1) × cos(lat2) × cos(Δlon) bearing = (atan2(y, x) × 180/π + 360) % 360 // 0° = North
